# 全应用代码审查：2026-10-27

更新：以下 6 项已在 Mac 1.0.3 / Windows 0.1.6 修复；原审查保留为历史依据，当前结果见文末“修复与验证”。

范围：当前工作区完整源码（含尚未提交的改动），Mac 1.0.2 / Windows 0.1.5；截图监听、归档和持久化、选择/拖放/预览、A/B/C 绘制与动效、设置、后台检查及构建打包入口。本轮仅审查，未修改产品代码或安装版本。

## 需要处理的发现

### 1. [P1] Windows 图片格式异常会静默终止监听任务

位置：`apps/windows/Jieliu.Core/CaptureWatcher.cs:126–143`；实际解码入口 `apps/windows/Jieliu.Windows/Model.cs:95–100`。

解码器可抛出 `FileFormatException`，其继承自 `FormatException`，不在 `Process` 的异常过滤范围内；外层 `Run` 也只处理 I/O、权限和取消异常。异常会令 worker 退出，后续截图不再接入，`Error` 事件却没有通知。换目录或退出时 `DisposeAsync` 再次抛出该异常，释放代码也不会继续执行。

后台用真实 CaptureWatcher 的维度解码委托注入同一异常继承链的 `FormatException`，观察到 `workerFaulted=True`、`reportedErrors=0`、后续正常输入 `subsequentCaptures=0`，DisposeAsync 再次抛出。Mac 无法运行 Windows WPF 编解码器，未把真实坏 PNG 的 WPF 解码记作已验证。异常继承关系经 [Microsoft 文档](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileformatexception?view=windowsdesktop-10.0)核对。

建议在 WPF 解码边界将可恢复的格式错误转成核心监听可处理、可报告的错误；单文件失败不应结束整个 worker。DisposeAsync 应在 worker 故障时仍释放资源并明确上报。

### 2. [P2] Mac A/C 入场动画仍使用旧版布局坐标

位置：`apps/macos/Sources/Jieliu/TrayView.swift:313–332`；调用处 `TrayController.swift:138–148`。

A 的绘制已按标签宽度排布，destinationRect 仍按图片宽度加 20 排布；C 的绘制使用新的 layerGap，destinationRect 仍使用旧的 128/8 公式。排队收纳的图片或已展开 C 的新图会飞向错误位置，在效果消失后跳到实际卡片位置。

使用产品相同源码和 Geist 字体离屏绘制，在 1100 宽视图、4 张 200×1000 的合成记录下，A 的目标与绘制中心依次相差 0、85.6、171.2、256.8 点；C 完全展开时相差 -40.5、-13.5、13.5、40.5 点。建议动画目标和绘制共享布局计算，并处理入场过程中展开间距变化。

### 3. [P2] Windows 缩略图只限制宽度，竖长截图可能被放大并大量占用内存

位置：`apps/windows/Jieliu.Windows/Model.cs:82–93`。

Image 固定传入 1000，LoadImage 只设置 DecodePixelWidth，既没有高度上限，也没有防止放大。WPF 按原比例计算高度；100×2000 的窄截图会请求 1000×20000 的位图。按 32 位像素估算，每张约 76 MiB，8 张约 610 MiB，尚未包含解码临时数据。加载又发生在界面绘制路径中，可能引起卡顿或内存压力。

这是根据代码和 [WPF 官方实现](https://source.dot.net/PresentationCore/System/Windows/Media/Imaging/BitmapImage.cs.html)计算的尺寸与内存估算，没有声称在 Windows 测得该内存值。Mac 使用最长边 1400 上限，没有同一问题。建议按最长边及原始尺寸决定缩略解码尺寸，避免放大；保持拖出/复制使用原图。

### 4. [P2] Mac 连续 Shift+方向键扩选停在第二张

位置：`apps/macos/Sources/Jieliu/TrayView.swift:415–420`。

每次移动都从“已选集合中第一个元素”计算下一项。第一步选入第二张后，第一张仍在集合中，下一步又回到同一个起点，无法继续扩选。后台向独立 NSView 发送三次合成 Shift+Right，实际选中 2 张，预期 4 张；没有注入真实键盘事件。Windows 会更新 anchor，没有这一相同问题。

建议维护独立的键盘当前项/扩选锚点，并覆盖正向、反向、普通多选后的移动及截图淘汰场景。

### 5. [P3] Mac 关闭动效会连带关闭已启用的收纳音效

位置：`apps/macos/Sources/Jieliu/TrayController.swift:138–149`。

播放声音只放在 EffectWindow 完成回调里。关闭应用动效或启用系统减少动态效果后，提前返回，不会进入播放声音的代码，尽管“收纳音效”仍显示开启。此项通过调用路径确认，没有播放声音或创建窗口。建议按成功收纳独立触发声音，避免把音效开关与动画开关绑定。

### 6. [P3] Mac 两个 DMG 打包脚本仍硬编码 1.0.0

位置：`scripts/release.sh:15–19`、`scripts/package-local.sh:10`。

当前应用已为 1.0.2，脚本仍输出 Jieliu-1.0.0.dmg / Jieliu-1.0.0-local.dmg，并启用覆盖。后续运行将得到版本标签错误的安装包，还可能覆盖此前同名 DMG。当前交付 ZIP 不受此问题影响。建议与 Windows 构建脚本一样，从应用元数据读取版本，并统一用于打包、签名及公证路径。

## 修复与验证：Mac 1.0.3 / Windows 0.1.6

1. **格式异常与监听生命周期：** Windows 核心按可恢复图片格式异常处理，保留原文件并继续接收后续图片，文件写完整后可重试。非预期 worker 故障明确报告并继续向调用方传播，DisposeAsync 的 finally 保证释放信号及取消源。缩略解码的格式/权限错误也会报告而不直接终止界面。跨平台回归覆盖格式异常后继续接收、原文件保留、完成后恢复，以及非预期故障的报告和资源释放。Windows 原生回归补入真正的 FileFormatException、后续 PNG 解码及坏缩略图报告；尚待 Windows 执行。Mac 实际目录监听也验证了坏 PNG 不阻塞后续截图、完成后能恢复。
2. **动画落点：** Mac A 复用 rulerLayout；C 的绘制、命中、入场终态复用 LayerPlacement。效果每帧按当前布局更新目标，覆盖展开、悬停及连续新图引起的位移；A 标签按最终尺寸预留空间，避免数字增长改变排布。离屏检查覆盖 A/C 多种展开程度、视图宽度与悬停姿态，验证效果终态与实际可见路径一致；连续来图时正在飞入的图片继续跟随当前列。Windows 已使用相同投影姿态作为终态，沿用 C 投影/纹理/点击与布局切换检查。
3. **缩略尺寸：** Windows 最长边限制为 1000，且不放大小图；原图预览、复制和拖放仍使用原始尺寸。核心检查覆盖窄长、超宽、大图、小图和极窄比例。WPF 原生实际像素尺寸及原图尺寸检查随包交付。Mac 已有最长边 1400 上限，本轮通过真实 PNG 解码验证了竖长图及小图的边界。
4. **键盘扩选：** Mac 保存独立键盘当前项，点击及辅助功能选择时更新，样式变化或淘汰时清理，不再从选中集合第一项反复起步。后台合成事件覆盖连续左右扩选、点击后恢复移动及旧项淘汰。Windows 键盘移动提取为真实 UI 调用的核心规则，覆盖相同场景；保留两端原有边界行为（Mac 循环、Windows 停在边界）。
5. **音效：** Mac 按成功收纳记录触发声音，与动画完成回调分离。无窗口测试通过声音替身验证应用动效开关、系统减少动态效果、声音开关及重复记录只触发一次，未播放真实声音。Windows 当前未提供这一音效开关，本轮未扩展音效功能。
6. **打包版本：** 两个 Mac DMG 脚本从实际应用 Info.plist 读取版本，签名、公证 ZIP 与 DMG 使用同一版本；支持 APP_OUTPUT 指定暂存应用。用模拟外部工具验证 9.8.7 和 1.0.3 两种版本及非法版本拒绝，未执行真实 DMG、公证或发布。

后台入口固定为 `scripts/macos-background-check.sh`：默认执行模拟打包检查、核心检查和固定 `--offscreen-check`；传入最终可执行文件绝对路径时只执行同一无窗口检查。测试用假可执行文件核对了参数和错误路径拒绝。README 与 AGENTS 已记录这一边界，本次未使用普通启动或预览入口。

已通过：Mac 核心、调试版及最终 Release 包的离屏回归；Windows 核心 8 组回归、原生检查交叉编译及 x64 自包含发布；模拟打包和后台入口检查；Bash 语法、差异空白检查。Mac Release 仍有本机工具链缺失搜索目录的非阻断警告；Windows 发布未执行在线依赖漏洞审计。
