# Windows 0.1.2：一次完整验收

## 这次要确认的真实任务

整理一组准备放入工作文档或发送给同事参考的截图：正常截图，使用 C 找图和预览，使用 B 继续收纳，再把原图拖进你平时用的一个应用。

建议一次预留约 8–12 分钟，时间只是估计；只做这一轮，最后统一反馈。无需逐项回到聊天确认，也无需重复已确认的普通文件操作。仅由你方便时自行操作 Windows；本轮没有任何自动前台操作或鼠标键盘接管。

必须由 Windows 实机确认的原因：Mac 上能编译 Windows 程序、验证几何和粒子时间线，但不能运行 WPF。新动效是否流畅、倾斜图片的实际点击与拖放是否准确，是当前影响真实使用的关键缺口。多屏混合 DPI 不另设一轮测试，只在你平时已经使用的显示器环境观察。

## 开始前一次准备

1. 保留 0.1.1 文件夹和 ZIP，退出托盘中的旧版。解压 0.1.2 到独立目录，再运行 `Jieliu.exe`，不要覆盖旧版。
2. 设置标题应显示 **0.1.2**。应用身份、配置路径和截图目录沿用原版，无需重新选择目录或迁移历史；只确认当前接入目录与你截图工具的自动保存目录一致。
3. 要观察动效，应用「界面动效」和 Windows「辅助功能 → 视觉效果 → 动画效果」需开启。如果你因辅助需求关闭系统动画，可以保留设置并明确反馈“本轮未验收动画”，不要为测试勉强改变偏好。

## 完成一段截图整理工作

**先用 C 选图。** 选择 C，正常截取 3 张有实际用途的内容，至少包含一张宽图、一张竖图。观察新图是否先抬起并翻转，再以倾角落入图层；鼠标进入图层区域应展开，离开后重新叠起。悬停时图片应转正、适度放大并来到最上层。选择一张较旧图、再多选另一张，用 Space 看原图，再把它们拖进平时使用的文档、聊天输入框或邮件草稿。无需真实发送。整个过程中关注：点的是哪张，实际选中和拖出的是否就是哪张，而不是旁边的透明空白区域。

**再用 B 接着收纳。** 切换 B，再截取 6 张本来就要整理的内容，其中两张可以连续截图。本轮总计 9 张用于覆盖环形淘汰，避免额外制造测试文件。观察是否出现源浮卡扫描、彩色像素汇聚、READ → WRITE 扫描恢复清晰原图；原槽位被覆盖时，旧图像素应向右上归档按钮收拢并消失。最后画面要稳定、图片清晰，不能残留粒子、长时间停在 READ/WRITE，或少收新图。

**收尾。** 从托盘移出一张不再需要的记录，确认归档文件仍在；关闭后重开托盘，确认没有残留浮卡或遮挡。若动效期间本来就需要切换样式或暂时关闭动画，可以正常操作，不必刻意反复打断。把准备好的截图留在上述工作文档或草稿中，完成这次整理即可。

HTML 中 C 的“主动移出”是短淡出，“容量淘汰”才是向归档按钮缩小；像素粒子属于 B。包内 `REFERENCE.html` 可选作对照，不要求你逐帧核对参数。

## 一次反馈

结束后统一提供以下信息即可：

- 这组截图是否成功收纳、正确选择并拖出；如失败，在哪个阶段。
- C 的翻转/堆叠/悬停、B 的汇聚/扫描/淘汰：正常，或最明显的一个问题。
- 如有异常，设置中点一次「导出动效诊断」，把 JSON 与上述反馈一起给我。诊断只包含版本、系统动画开关、渲染能力、阶段、计数及 CPU 绘制耗时，不含截图像素、文件名、路径或凭据。CPU 绘制耗时不是显示器帧率。
- 只有异常难以描述时，再附一段短录屏；避开敏感内容，不必重做整轮。

遇到崩溃、明显遮挡工作、选错图或原文件异常，立即停止新版，不要重试循环。退出 0.1.2，运行保留的 0.1.1 即可回退；不用删除截图目录或重新配置。

## 已知边界，不算本次新故障

落盘截图不提供可靠的原屏幕坐标，所以 C 浮卡和 B 像素从托盘附近开始，不会从真实截图区域飞来；仍按鼠标所在屏幕展开。仅剪贴板截图不接入。包未签名。HTML 的声音和完整桌面模拟不属于本次改动。
