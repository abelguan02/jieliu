# Mac 1.0.1：双端共同交互补齐

本轮对齐 Windows 0.1.4 已修复的交互要求。两个版本独立使用原生代码，版本号不同；本次不替换或启动用户当前运行的 Mac 应用，也不修改 Windows 包。

## 已修改

- **动画期间选图：** Mac 的入场效果原先位于整个穿透窗口中。现在按实际画出的图片/粒子区域接收点击，转交同一张图片的选择、预览与拖动；无图区域继续穿透。按住图片期间不因动画自然结束而丢弃点击。
- **展开时点击：** A/C 使用当帧平移后的命中路径，C 使用实际投影四边形；B 使用展开中的圆角裁切范围。图片看得见时可选，不再依赖“已完全展开”的状态；不可见区域不参与图片命中。
- **连续截图：** 淘汰旧图后，按下、松开、拖动和辅助功能选择都会校验当前历史；样式变化取消待提交选择。队列过滤已经淘汰的图片，取消效果后过期回调不会重新推进旧动画。
- **关闭动效：** 新增应用内“界面动效”，与系统“减少动态效果”共同决定是否播放。关闭时取消独立效果窗口及队列，清除 landing、READ/WRITE、尺寸增长、移出效果，展开/悬停直接到终态；重新开启不回放旧效果。虚框和写入指针在关闭动效后保持静态。
- **共同规则：** 已写入根目录 AGENTS.md：以后共同交互必须同步核对两端，分别报告验证情况，前台测试仍需当前空闲确认。

## 后台回归

新增 `scripts/macos-background-check.sh`，运行 CoreChecks 和 `--offscreen-check`。后者禁用应用激活，直接离屏绘制 NSView，只使用临时合成图片和独立偏好域，不运行旧的会弹窗的 `--integration-check`。

覆盖 A/B/C 多个展开进度的命中与合成点击、C 投影区域、A/B/C 入场效果多个阶段的可见路径和选择回调、连续 40 条记录下的淘汰/松开、样式切换、应用动效/模拟系统减少动态效果、关闭后重新开启、无窗口队列清理及原文件保留。另覆盖“写到第 5 格、选第 2 格，下一张仍写第 6 格”。

开发环境最初默认缓存写入受限，改用项目内构建缓存解决；这是构建路径问题，不是应用运行失败。编译器仍提示本机 Command Line Tools 中的搜索目录缺失，构建结果单独核对。

## 剩余验证边界

本轮结果：5 项核心检查通过；调试版离屏回归通过；最终发布包内同一离屏回归通过，并断言没有可见窗口；Release 构建及严格本地签名校验通过。默认缓存、调试符号生成及 AppKit 注册曾受沙箱限制，切换项目缓存并仅对后台构建/离屏入口使用获准执行后完成。没有把受阻运行记作测试通过。

Windows 继续保留 0.1.4：其核心回归与交叉编译已通过，Windows WPF 与真实交互仍未在本机运行。本轮 Mac 修复不意味着 Windows 运行验证已经完成。

离屏绘制和合成事件不等于真实桌面验证。本轮没有启动可见应用窗口、自动截图、真实键鼠注入或外部应用拖放。独立效果窗口的真实鼠标路由、跨窗口拖动、真实系统设置通知以及目标机器流畅度仍未前台验证；不要求用户现在逐项测试。

以后安排验收时，只需一次实际截图整理任务：收集几张可辨认内容，在展开/入场时选图，切换 A/B/C，暂停/恢复动效，再把选好的图片拖入一份文档或消息草稿；统一反馈错误即可。已覆盖的容量、过期选择和队列时序不要求人工追赶复现。

旧版 dist/截留.app 保留；新包位于独立的 Jieliu-mac-arm64-1.0.1 目录。Bundle ID、配置路径与原版一致，采用本地临时签名，未做 Developer ID 公证；不能承诺系统更新后永远不再询问权限。未发布 GitHub、未创建提交。
